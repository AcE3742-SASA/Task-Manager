# SASA Task Manager

세종과학예술영재학교(SASA) 학사 구조에 맞춘 개인용 할일 관리 웹앱 / PWA.

---

## Problem

SASA 학생의 과제 정보는 Google Classroom, 반 메신저, 종이 프린트, 수업 중 구두 공지로 흩어져 들어온다. 한 곳에 모으려면 매번 손으로 옮겨 적어야 하고, 옮기는 과정에서 기한이 누락되거나 아예 등록되지 않는다. 일반 투두 앱은 "과목"이라는 개념도, "다음 수업 전까지"라는 이 학교의 실제 마감 규칙도 모르기 때문에 기한을 매번 수동으로 계산해 넣어야 하고, 그 마찰 때문에 결국 쓰지 않게 된다. 해결하지 않으면 제출 누락과 마감 직전 벼락치기가 계속된다.

## Evidence

- 사용자 본인 진술 (2026-08-20): 과제 공지가 Google Classroom · 반 메신저 · 메모에 흩어져 있어 한눈에 보는 곳이 없다.
- 사용자 본인 진술 (2026-08-20): 기존 투두 앱을 써봤으나 맞지 않아 정착에 실패했다. 어느 앱을 어떤 이유로 이탈했는지는 미확인.
- **Assumption — needs validation**: "기존 앱이 안 맞은 이유 = 과목/시간표 개념 부재로 인한 입력 마찰"이라는 인과는 아직 검증되지 않았다. 1차 릴리스 사용 후 본인 회고로 검증한다.
- 도입 전 마감 누락 건수는 측정하지 않기로 했다 (2026-08-20 결정). 개선 폭 대신 절대값 0건을 목표로 삼는다.

시간표 구조는 AcEVault 위키 `coursework-2026-2학기-시간표`로 실물 확인됨. 아래 "학사 구조 사실"은 가설이 아니라 확인된 사실이다.

### 확인된 SASA 학사 구조 사실

- 1일 최대 9교시(8:40~18:10) + 점심(12:30~13:20). 10교시(19:00~19:50) 칸이 시간표 양식에 존재한다.
- **팀티칭이 흔하다.** 같은 과목이 서로 다른 요일·교시에 다른 교사 이름으로 등장한다 (예: 인공지능 = 월1교시 임건웅 + 월8~9교시 이현아, 일반물리학Ⅰ = 수3~4교시 조승훈 + 금3~4교시 김승진, 미적분학Ⅰ = 월5~6교시 길승호 + 월7교시 고민지). 따라서 **"과목"과 "시간표 슬롯"은 1:N이며, 교사는 과목이 아니라 슬롯에 붙는다.**
- 시간표에 교과가 아닌 블록이 정규 배정된다 (수5~7교시 "연구활동", 금5교시 "창의적 체험활동"). 담당교사·강의실이 없다.
- 한 학생이 한 학기에 듣는 과목 수는 10개 안팎.

## Users

- **Primary**: 홍이준 (SASA 2학년). 수업 직후 또는 귀가 후 그날 받은 과제를 몰아서 입력하고, 아침·저녁에 오늘/내일 할 일을 확인한다. 맥(웹)에서 주로 입력하고, 아이폰(PWA)에서 주로 확인한다.
- **Secondary (예정, MVP 아님)**: 같은 학교 친구 몇 명. 각자 로그인해 각자의 시간표와 할일을 가지며, 데이터는 공유되지 않는다.
- **Not for**: SASA 전교생 대상 공개 서비스. 교사·학부모. 조별과제 협업이나 할일 공유가 필요한 사용자. 학사 시스템 연동을 기대하는 사용자.

## Hypothesis

We believe **과목·시간표를 1급 개념으로 다루고 "다음 주 수업 전날"을 기한 기본값으로 자동 계산해주는 할일 앱**이 **분산된 과제 정보를 옮겨 적는 마찰과 기한 수동 계산 부담**을 **SASA 학생 본인**에게서 없앨 것이라 믿는다.

We'll know we're right when **한 학기(약 16주) 동안 본인이 이 앱을 유일한 할일 관리 도구로 계속 쓰고, 과제 하나를 등록하는 데 30초를 넘지 않으며, 기한을 놓친 과제가 0건일 때** 알 수 있다.

## Success Metrics

| Metric | Target | How measured |
|---|---|---|
| 도구 대체 (primary) | 2주 연속, 주 5일 이상 앱 실행 | 앱 내 세션 로그. 병행 사용 여부는 주간 자가 보고. |
| 등록 소요 시간 | 과제 1건 등록 ≤ 30초 (중앙값) | New 화면 진입 → 저장까지 클라이언트 타이밍 기록 |
| 놓친 마감 | 학기 중 0건 | 기한 경과 후 완료 처리된 task 수 |
| 자동 기한 채택률 | 자동 계산된 기한을 수정 없이 저장하는 비율 ≥ 70% | 저장 시 기한이 기본값과 동일한지 기록 |

> 자동 기한 채택률은 핵심 가설의 직접 검증 지표다. 이 값이 낮으면 "다음 주 수업 전날" 규칙 자체가 틀린 것이므로 규칙을 재설계한다.
>
> "놓친 마감 0건"은 도입 전 기준선을 수집하지 않는다. 개선 폭이 아니라 절대값 0건만 본다.

## Scope

### MVP — 매일 쓰기 시작할 수 있는 최소한

1. **Google 로그인 + 기기 간 동기화.** 맥에서 등록하고 아이폰에서 본다. 이게 없으면 폰 PWA가 무의미하다.
2. **시간표 설정.** 과목을 먼저 등록(이름 · **줄임말** · 색 · 아이콘)하고, 그 과목을 요일×교시 격자에 배치한다.
   - **줄임말**은 과목마다 사용자가 직접 등록하는 필드이며 **최대 3글자**다. 자동 축약은 하지 않는다 — 앞 세 글자로 자르면 "일반물리학I"과 "일반물리학실험I"이 둘 다 "일반물"이 돼 구분이 사라지기 때문이다. 시간표 격자와 주간 뷰가 이 값을 표시한다.
   - **아이콘**은 앱이 제공하는 **고정 40종 세트**에서 고른다. 6개 축으로 구성한다: 수학·과학 10 / 컴퓨터 5 / 언어·인문 6 / 예체능 6 / 연구·프로젝트 5 / 일반 8. 사용자 업로드는 없다. 한 과목이 여러 슬롯을 갖는 팀티칭 구조를 전제로 한다. 슬롯에는 교사·강의실을 선택 입력한다. 교과가 아닌 블록("연구활동", "창의적 체험활동" 등)도 과목과 **동일하게** 취급한다 — 시간표에 배치되고, task를 붙일 수 있고, 자동 기한 계산도 똑같이 적용된다.
3. **과목 기반 자동 기한.** task 생성 시 과목을 고르면 기한이 자동으로 채워지고, 그 자리에서 수정 가능하다. 규칙은 아래 "기한 계산 규칙" 참조.
4. **List View.** Today / Tomorrow / This Week / Later / Completed 그룹. 각 항목은 왼쪽부터 과목 아이콘 → 제목(크게) + 과목명(아래, 회색) → 기한(시간까지) → 체크박스. 본문 영역을 누르면 상세 모달(수정·삭제), 체크박스를 눌러야만 완료 상태가 바뀐다.
5. **task 등록/수정/삭제.** 필드: 제목, 과목, 내용, 기한, **과제 종류**(과제 / 수행평가 / 시험 / 개인). 과제 종류는 **표시 전용**이다 — 목록에서 라벨로 보일 뿐 정렬·필터·기한 계산에 관여하지 않는다.
6. **Calendar View.** 월간·주간 토글.
   - **월간**: 날짜 격자에 과목 색 표시, 날짜를 누르면 그 날 마감 목록.
   - **주간**: **시간표를 표시하지 않는다.** 그 주 7일의 날짜 스트립(요일 · 날짜 · 마감 건수)과 그 아래 날짜별 마감 목록으로 구성한다. 시간표는 매주 동일해 볼 이유가 없고, 9교시 × 5일 격자를 390px에 넣으면 과목명이 뭉개진다. 할 일 행은 List View와 같은 컴포넌트를 쓴다.
7. **Settings / Profile 기본.** 주 시작 요일(월/일), 언어(한/영), 시간표 설정 진입, 버전 정보, 개발자 정보, 계정 삭제. 다크 모드는 Release 2.
8. **PWA 설치.** 아이폰 홈 화면 추가 유도 및 데스크탑 설치.
9. **학기 초기화.** 새 학기를 시작하면 시간표와 task를 비운다. 과거 기록은 보존하지 않는다.

### Out of scope (MVP)

- **푸시 알림** — 사용자가 MVP 필수에서 제외. Release 2로 이동. 알림 없이도 앱을 열어 확인하는 흐름은 성립한다.
- **다크 모드** — Release 2. 라이트 모드에서 5색의 역할이 확정된 뒤에 옮기는 게 순서상 맞다.
- **과거 학기 기록 보존** — 학기 전환은 초기화로 처리한다. 지난 학기 과제를 다시 볼 일이 없다는 판단.
- **Android 푸시** — 사용 기기가 아이폰과 데스크탑. 웹 표준을 따르므로 나중에 자동으로 따라오지만 검증 대상은 아니다.
- **시간표 이미지/텍스트 자동 인식** — 정확도가 불안정하고 학기당 1회 하는 작업이라 수동 입력 대비 이득이 작다.
- **다중 사용자 공유·협업** — 조별과제 공유, 반 전체 과제 목록, 할일 위임 등 일절 없음. 단, 데이터 모델은 사용자별 격리를 전제로 설계해 나중에 친구를 추가할 때 재작업이 없게 한다.
- **Google Classroom 연동 자동 임포트** — 인증 범위·승인 절차 부담이 크다. 수동 입력이 실제로 병목인지 먼저 확인한다.
- **하위 체크리스트 / 파일 첨부 / 반복 task / 우선순위** — 필드를 늘리면 "등록 30초" 목표와 정면 충돌한다. 실사용 후 판단.
- **성적 관리, 출결, 학사 일정 연동** — 별개 제품.
- **오프라인 작성** — 조회 캐시는 PWA 특성상 따라오지만, 오프라인 상태에서의 편집·충돌 해소는 다루지 않는다.

### 기한 계산 규칙 (확정)

**기본값 = 다음 주 주간에 해당 과목이 처음 있는 수업일의 전날 23:59** (Asia/Seoul 기준).

- 같은 날 여러 교시(팀티칭)는 하루 1회로 묶는다. 교시가 아니라 **수업일**이 기준이다.
- 예: 인공지능(월1 + 월8~9). 월요일에 등록 → 다음 주 첫 수업일은 월요일 → 기한은 그 전날인 **일요일 23:59**.
- 예: 일반물리학Ⅰ(수3~4 + 금3~4). 수요일에 등록 → 다음 주 첫 수업일은 수요일 → 기한은 **화요일 23:59**. 같은 과목을 금요일에 등록해도 결과는 동일하다.
- "다음 주"의 경계는 Settings의 주 시작 요일(월/일)을 따른다.
- **"다음 주"를 계산할 수 없으면 등록 시점 + 7일, 23:59로 둔다.** 주말이나 방학처럼 다음 수업일이 모호한 경우에 적용한다. 규칙을 정교하게 만들지 않고 단순한 기본값으로 후퇴한다.
- 과목을 고르지 않은 개인 할일은 자동 기한이 없다. 사용자가 직접 지정한다.
- 자동 계산 결과는 **항상 사용자가 그 자리에서 수정할 수 있다.** 자동값은 제안이지 강제가 아니다.

## Design Direction

- **스타일**: Neubrutalism — 두꺼운 아웃라인, 하드 섀도우(블러 0), 각진 모서리, 큰 타이포, 명확한 면 분할.
- **팔레트** (사용자 지정, 이 4색 기반):

  | 역할 | HEX |
  |---|---|
  | 아웃라인 · 하드 섀도우 · 본문 텍스트 | `#34170D` |
  | 주 강조 / 세이지 | `#8FA28A` |
  | 보조 면 / 라이트 세이지 | `#C7D3C0` |
  | 배경 / 크림 | `#F7F4ED` |
  | 액센트 / 탄 | `#C8A96B` |

- **아웃라인은 검정이 아니라 `#34170D`(진한 에스프레소 브라운).** 전형적 neubrutalism의 순검정 테두리 대신 이 색을 쓴다. 크림 배경 위 대비가 충분히 높아 두꺼운 테두리와 하드 섀도우가 제대로 서고, 액센트 탄(`#C8A96B`)과 같은 웜 계열이라 팔레트 전체를 따뜻한 축으로 묶는다. 세이지 2색이 그 안에서 차가운 대비 역할을 한다.
- **폰트**: Moneygraphy-Rounded(본문·제목), Moneygraphy-Pixel(액센트·숫자·라벨). 상업적 사용 가능 확인됨.
- **로마숫자 제약 (2026-08-20 시안 작업 중 발견)**: 두 서체 모두 `U+2160`(Ⅰ)~`U+2163`(Ⅳ) 글리프가 **없다**. 학사 시스템에서 복사한 과목명("일반물리학Ⅰ", "체육Ⅳ", "미적분학Ⅰ", "프로젝트기반연구Ⅰ")을 그대로 저장하면 그 한 글자만 시스템 폰트로 튄다. 앱은 과목명 저장 시 로마숫자를 ASCII(`I`, `II`, `III`, `IV`)로 정규화해야 한다.
- **과목 구분**: 지정된 아이콘 세트에서 선택 + 과목별 색상.
- **네비게이션**: 하단 바 5개 — List · Calendar · New · Settings(톱니바퀴) · Profile. New는 가운데, ink로 채운 사각형.
- **과목 아이콘**: 24px 뷰박스, 스트로크 1.9px, 채움 없음. 색이 아니라 형태로 과목을 구분한다 — 흑백 출력이나 색각이상에서도 읽히게 하기 위해서다.

> Release 1은 **라이트 모드만** 만든다. 다크 모드는 Release 2에서 이 5색의 역할을 다크 그라운드로 옮기는 작업으로 다룬다.

## Ownership — 사용자가 직접 해야 하는 일 vs 에이전트가 할 수 있는 일

사용자가 요청한 구분이다. 구체적 절차는 `/plan` 단계에서 마일스톤별 체크리스트로 전개한다.

**사용자만 할 수 있는 일 (계정·권한·비밀정보)**
- Firebase 프로젝트 생성, 요금제 선택, 인증 공급자로 Google 활성화
- 승인된 도메인 등록 (배포 주소 + 로컬 개발 주소)
- Vercel 계정 연결 및 배포 대상 저장소 승인
- 각종 키·시크릿을 배포 환경 변수로 등록 (에이전트에게 값을 알려줄 필요 없음)
- 푸시 알림용 키 발급 및 실제 기기에서 알림 권한 허용 (마일스톤 6)
- 아이폰에서 홈 화면 추가 및 수신 확인 — 시뮬레이터로 대체 불가

**에이전트가 하는 일**
- 전체 애플리케이션 코드, 화면, 디자인 시스템 구현
- 데이터 구조 및 접근 규칙 작성 (사용자별 격리)
- 기한 계산 로직과 그 테스트
- PWA 설치 설정, 폰트 웹 변환 및 적용
- 배포 설정, 예약 알림 발송 로직 (마일스톤 6)
- 사용자가 해야 할 각 단계의 화면별 안내 문서
