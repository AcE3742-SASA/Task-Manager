# v1.5.0 출시 준비

작성일: 2026-09-19. 기준 버전은 `v1.4.0`, 기준 main 커밋은 `f6e244e`다. 앱 시작, 할 일 저장과 복구, 첫 사용 안내를 개선하고 예약 알림 호출을 cron-job.org로 옮긴다. 앱과 푸시 전송 API는 Vercel에 유지한다.

이 문서는 로컬 변경과 출시 전 확인 항목을 기록한다. 버전 번호를 바꾼 것만으로 배포나 예약 작업 전환이 완료되지는 않는다. 운영 예약 연결과 기기 수신 확인 상태는 [예약 알림 전환 절차](../cron-job-setup.md)에 기록한다.

## 사용자에게 달라지는 점

- 목록 외 화면을 필요할 때 불러오고 할 일 구독을 공유한다. 폰트는 사용한 테마부터 받아 캐시해 첫 설치의 다운로드 부담을 줄인다. 인증 확인이나 화면 로딩이 오래 걸리면 다시 불러올 수 있다.
- 오늘 할 일 창을 목록과 달력에만 표시해 작성, 수정, 설정 화면의 버튼을 가리지 않는다. 기존 압정 선택과 접힘 설정은 유지한다.
- 저장 대기와 실패를 표시하고 재시도할 수 있다. 새 할 일 초안은 이 기기에 계정별로 보관한다. 다른 기기에서 수정된 내용을 오래된 폼으로 덮어쓰려 하면 입력을 남기고 충돌을 알린다.
- 기한을 미룰 때 시각을 유지한다. 지난 기한은 같은 시각의 내일로 옮기며 되돌리기를 제공한다. 기한이 없는 할 일에는 날짜를 임의로 넣지 않는다.
- 빈 목록에서 과목 등록 없이 첫 할 일을 추가할 수 있다. 도움말은 건너뛰거나 내 정보에서 다시 볼 수 있다.
- 알림 권한, 기기 구독과 현재 계정의 연결을 함께 확인한다. 설정의 테스트 알림은 예약 실행을 기다리지 않고 인증된 API를 직접 호출한다.
- 데이터 가져오기 전에 파일을 검사하고 기존 데이터와 교체할 내용을 보여준다. 백업을 저장했는지 확인한 뒤 적용한다. 계정 삭제에 재인증이 필요하면 데이터 삭제 전에 요청한다.
- 메뉴, 입력 안내, 오류와 빈 화면의 한국어를 짧고 자연스럽게 정리했다. Moneygraphy 폰트 사용 조건과 공식 출처를 앱에서 확인할 수 있다.

목록 접기, 네 가지 테마, 과목과 시간표, 반복 할 일 등 기존 기능은 유지한다. 세부 구현과 이전 검증 근거는 [실사용 개선 기록](../usability-improvements.md)에 있다.

## 예약 알림 전환

cron-job.org가 Vercel의 알림 API를 호출하도록 전환한다. 반복 호출과 실패 재시도를 고려해 중복 억제, 제한된 재시도, 놓친 예약의 복구를 함께 다룬다. 전환 간격, 복구 범위, 인증 방식과 응답 제한은 [설정 문서](../cron-job-setup.md)를 따른다. 새 경로를 확인하기 전에 기존 GitHub 예약 실행을 끄지 않는다.

서버의 발송 성공은 푸시 서비스가 요청을 받아들였다는 뜻이다. iPhone에 표시된 시각과 같지 않으며, 정확히 한 번 도착하거나 정각에 도착한다고 보장하지 않는다. 스케줄러와 서버, Firestore 각각의 사용량과 실패 기록을 확인한다.

- [x] `npm test` 16개 파일 267개 통과, 타입 검사, 프로덕션 빌드와 `git diff --check` 통과. 초기 JS 778.55 kB 경고는 남아 있다.
- [x] 합성 데이터에서 반복·동시 호출, 부분 실패, 만료 경계, 전송 후 기록 실패와 구독 교체 경쟁 조건을 검증했다.

- [ ] 배포한 테스트 환경에서 인증 없는 알림 호출을 거부하고 필요한 서버 설정이 적용됐는지 확인한다.

- [ ] 새 예약 경로의 발송과 기기 수신 시각을 확인한 뒤 기존 예약 실행을 해제한다.

로컬 데모는 실제 Firebase 계정과 푸시 서비스를 사용하지 않는다. 데모 성공을 운영 로그인, 동기화나 푸시 도착 검증으로 대체하지 않는다. 실기기 검증에도 별도 테스트 계정과 합성 할 일만 사용한다.

## 출시 순서

저장소에는 전용 릴리스 자동화가 없다. 기존에는 버전을 직접 맞추고 테스트와 빌드를 실행한 뒤 커밋, 태그, 푸시를 진행했다. GitHub에 연결된 Vercel이 배포하는 구성은 [기존 배포 안내](../setup-firebase-vercel.md)에 설명돼 있다. 현재 연결과 운영 브랜치는 배포 전에 다시 확인한다.

1. 최종 변경 목록과 위 검증 결과를 확인한다. 앱 버전 표시, 폰트 사용 조건, 데이터 가져오기와 삭제 안내도 함께 검토한다.
2. 변경을 커밋하고 PR로 검토한다. 프리뷰 환경에서 테스트 계정으로 로그인과 PWA 갱신을 확인한다.
3. [예약 알림 전환 절차](../cron-job-setup.md)에 따라 서버 설정과 새 예약 작업을 준비한다. 서버 기록 정리 등 필요한 운영 설정은 [푸시 신뢰성 문서](../push-reliability.md)도 확인한다.
4. main 배포와 새 예약 경로를 확인한다. 환경변수를 변경했다면 재배포해 적용한다. 기존 예약의 해제 시점과 실패 시 복구 방법은 전환 문서에 따른다.
5. 확인한 출시 커밋에 `v1.5.0` 태그를 붙이고 변경 기록을 게시한다. 배포 URL, 커밋, 예약 전환 시각과 실기기 검증 결과를 기록한다.

## 남은 제한

처음 보는 테마를 오프라인에서 선택하면 아직 받지 않은 폰트는 대체 글꼴로 표시될 수 있다. 초안은 이 기기에만 보관하며 브라우저 저장소 삭제 후 복구를 제공하지 않는다. 다른 기기와 충돌한 편집 입력은 현재 폼에 남지만 모든 편집 폼을 종료 후 복구하는 기능은 없다.

가져오기는 최대 2 MB이며 기존 삭제와 신규 저장을 합친 작업이 500건을 넘으면 거부한다. 초기화와 계정 삭제도 한 번에 500문서까지 지원한다. 가져오기 직전 재조회와 쓰기 사이의 다른 기기 변경까지 잠그지는 않는다. Auth 계정 삭제와 Firestore 데이터 삭제는 하나의 transaction이 아니므로 부분 완료 가능성을 별도로 안내한다.
