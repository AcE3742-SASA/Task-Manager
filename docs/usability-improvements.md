# 실사용 개선 구현과 검증 — 2026-09-18

기준은 최신 `origin/main`의 `f6e244e`(PR #10 테마 병합)이며, 작업 브랜치는 `codex/usability-improvements`다. 기존 목록 접기, 네 테마, 최대 폭 480px, 하단 다섯 메뉴를 유지했다. 실제 계정 쓰기, 실제 알림 발송, 외부 데이터 전송과 배포는 수행하지 않았다.

## 반영한 범위

| 범위 | 구현 |
|---|---|
| 1. 시작 부담 | 목록 외 화면을 지연 로드한다. 목록·달력·오늘 할 일의 task 구독은 Shell에서 공유한다. 선택하지 않은 폰트의 강제 preload와 전체 폰트 precache를 없애고 기존 Workbox의 CacheFirst로 사용한 서체를 보관한다. 인증 확인이 지연되거나 화면 청크를 못 받으면 안내와 다시 불러오기를 제공한다. |
| 2. 입력 화면 가림 | 오늘 할 일 창은 목록·달력에서만 표시한다. 작성·수정·설정·시간표에서는 저장 버튼을 가리지 않는다. 압정 선택과 기존 접힘 설정은 유지한다. |
| 3. 저장 신뢰성 | 할 일·압정·설정의 저장 대기와 실패·재시도를 표시한다. Firestore의 pending/fromCache를 구분하며 캐시 응답을 오프라인 확정으로 취급하지 않는다. 새 할 일의 초안은 UID별 기기 저장소에 남기고 같은 초안 ID 재제출은 중복생성을 막는다. 다른 기기 편집과 충돌하면 입력을 남기고 최신 내용을 확인하게 한다. |
| 4. 기한 변경 | 기존 시각을 유지해 기한을 하루 뒤로 옮긴다. 이미 지난 날짜는 같은 시각의 내일로 옮긴다. 날짜·시각과 되돌리기를 표시하며 다른 기기에서 바뀌었거나 완료된 항목에는 오래된 Undo를 적용하지 않는다. 기한 없는 항목에 날짜를 임의로 만들지 않는다. |
| 5. 첫 할 일 | 빈 목록에서 바로 추가할 수 있고 과목 없이도 저장한다. 로그인 직후 빈 캐시만으로 새 사용자라고 단정하지 않는다. |
| 6. 알림 | 브라우저 권한·구독·현재 계정의 서버 등록·VAPID를 확인한다. 계정 전환과 로그아웃 때 이전 기기 연결을 정리하고 실패를 알린다. 사용자가 누르는 인증된 테스트 알림 API, 발송 실패 집계와 cron 실패 상태를 추가했다. |
| 7. 데이터 보존 | JSON의 전체 구조·ID·타입·날짜·시간표·설정을 먼저 검사한다. 기존/신규 건수를 확인하고 백업 저장 확인 후 단일 batch로 교체한다. 오래된 로그인은 데이터 삭제 전에 재인증한다. |
| 튜토리얼 | `/help`에서 기록→오늘 할 일 고르기→과목·시간표 연결을 설명한다. 건너뛰기 가능, UID별 완료 기억, 내 정보에서 다시 열기. 강제 과목 등록이나 알림 권한 요청은 없다. |
| 한국어 | 내비게이션·폼·설정·오류·빈 목록·알림 문구를 짧은 앱 문체로 통일했다. 입력 label과 확대 허용도 보완했다. 저장된 kind 등의 내부 값은 바꾸지 않았다. |
| 폰트 | `public/fonts/Moneygraphy-LICENSE.txt`에 공식 사용 조건과 출처를 기록했다. 내 정보에서 열 수 있다. 기존 Rounded/Pixel woff2가 공식 1.1 zip과 바이트 단위로 일치한다. |

## 성능에서 확인한 수치

원본 main을 임시 폴더에서 별도로 빌드하여 비교했다. 아래는 다운로드 대상 파일 크기이며 iPhone의 로딩 시간 측정값이 아니다.

| 항목 | main | 개선 구현 |
|---|---:|---:|
| 초기 앱 JS, 압축 전 | 801.70 kB | 약 779 kB |
| 초기 앱 JS, gzip | 213.18 kB | 약 207 kB |
| PWA 설치 precache 전체 | 4631.39 KiB | 약 956 KiB |

설치 precache는 약 79% 줄었다. Firebase SDK가 포함된 초기 JS의 500 kB 경고는 남아 있다. 실제 시작 지연의 원인이 인증·네트워크·JS·기기 성능 중 어디에 있는지는 iPhone에서 추가로 측정해야 한다.

개발자 도구에서 `performance.getEntriesByName('app:auth-ready')`와 `performance.getEntriesByName('app:tasks-visible')`로 이번 페이지 진입 이후 인증 확인과 첫 목록 표시 시점을 볼 수 있다. 후자는 목록 경로에서 실제 항목이 있거나 서버가 빈 목록을 확인했을 때 기록한다. 외부 분석 서버로 보내지 않는다. 캐시 목록 표시와 서버 최신 데이터 확인은 동일한 지표가 아니다.

폰트는 해당 테마를 온라인으로 사용해 캐시한 뒤 오프라인에서 재사용한다. 처음 보는 테마를 오프라인에서 고르면 아직 받지 않은 서체는 대체 글꼴로 표시될 수 있다. `/__/auth/`와 `/api/`는 계속 SPA 캐시 예외다. 폰트 파일을 같은 이름으로 바꿀 때 `sasa-fonts-v1`의 버전도 올린다.

## 검증

- 단위 테스트 13개 파일, 205개 통과. 반복 완료 동시성, 초안 재제출, 편집 충돌, Undo 충돌, 초안 비교 후 삭제, import 검증·단일 batch, 재인증 실패 시 쓰기 0회, 알림 계정 격리·인증·요청 제한·부분 발송 실패·설정별 실패 보존을 포함한다.
- `npm run typecheck`, `npm run build`, `git diff --check` 통과.
- 기존 `scripts/check-demo.mjs`: 네 테마 전환·재실행, 할 일 생성·완료·수정·삭제, 달력 통과.
- `scripts/check-usability.mjs`: 390×844 모바일에서 접기·초안 복원·가려지지 않는 저장 버튼·12:34 기한 유지와 Undo·기한 없는 항목·잘못된 import의 쓰기 0회·백업 후 실제 합성 import·빈 목록·튜토리얼 통과. 1440×1000 도움말도 확인했다. 외부 요청과 페이지 오류 0건.
- 데모 Firebase alias와 프로덕션 서비스워커를 결합한 별도 로컬 빌드에서 SW 설치/제어, 사용한 폰트 11개 캐시, offline reload와 지연 로드 화면 이동을 확인했다. 이는 실제 인증·Firestore 오프라인 쓰기·푸시 수신 검증이 아니다.
- 화면과 합성 테스트 자료: `outputs/usability-implementation/`.

재실행 시 기존 Playwright 설치를 사용한다. 프로젝트에 새 브라우저 프레임워크를 추가하지 않았다.

```sh
npm run dev:demo -- --port 5190
# 다른 터미널: PLAYWRIGHT_MODULE은 설치된 playwright/index.mjs의 절대 경로
DEMO_URL=http://127.0.0.1:5190 node scripts/check-usability.mjs
```

## 상호 검토로 고친 예외

- 같은 초안 ID를 다시 받으면 무조건 성공 처리하던 안을 수정했다. 기존 내용과 다른 입력이면 초안을 남기고 기존 항목 보기/새 항목으로 저장을 제공한다.
- 이전 화면의 늦은 저장 응답이 최신 초안을 지우지 않도록 제출 당시 초안과 현재 저장된 초안을 비교한다.
- 폼을 연 이후 다른 기기에서 변경된 내용은 transaction으로 감지한다. 오래된 폼이 새 메모·기한을 덮지 않는다.
- transaction에서 오프라인 자동 저장을 보장하는 문구를 없앴다. 오프라인 실패 시 연결 후 직접 재시도해야 할 수 있다.
- 실제로 삭제된 과목을 참조하는 기존 할 일은 유효한 과거 데이터이므로 보존하고 가져오기 미리보기에 알린다.
- 새 테스트 푸시는 기존 서비스워커의 `screen` 계약과 맞췄다.
- ponytail 관점에서 새 큐·일반화된 repository 계층·중복 저장 API를 피했다. 더 이상 호출하지 않는 `saveNotify`와 `isSubscribedHere`도 정리했다.

## 출시 전에 남은 확인

1. 실제 iPhone 홈 화면 PWA에서 콜드 시작·재실행·백그라운드 복귀를 비교한다. 새 SW 업데이트 후 선택한 테마 폰트를 온라인에서 한 번 불러온 뒤 비행기 모드 재실행도 확인한다.
2. 별도 테스트 계정 두 개로 실제 Google 리다이렉트 로그인, 두 기기 변경 충돌, 오프라인 후 재접속, 계정 전환을 확인한다. 현재 단위 테스트의 Firestore/Auth는 합성이다.
3. 실제 iPhone에서 테스트 알림 수신·클릭·권한 거절·재연결·로그아웃을 확인한다. 스케줄러의 정확한 정각 전달을 보장하지 않는다.
4. 9월 18일에는 `pushTestLimits.expiresAt`의 TTL 정책을 출시 전 과제로 남겼다. 9월 19일 v1.5.0에서는 예약 실행이 만료 기록을 배치 정리하도록 변경해 별도 TTL 정책이 필수는 아니다. 현재 절차는 [푸시 신뢰성](push-reliability.md)을 따른다.

가져오기는 최대 2 MB이며 기존 삭제와 신규 저장을 합친 실제 작업이 500건을 넘으면 쓰기 전에 거부한다. 초기화/계정 삭제도 한 번에 500문서까지 지원한다. 가져오기 직전 재조회로 변경을 확인하지만, 재조회와 batch 사이의 다른 기기 동시 쓰기까지 잠그지는 않는다. Auth와 Firestore의 계정 삭제는 하나의 transaction이 될 수 없으므로 데이터 삭제 이후 Auth 실패는 완료된 범위를 명확히 알려준다.

새 할 일 초안은 이 기기의 계정별 저장소에 남는다. 기기 간 초안 동기화와 브라우저 저장소 삭제 후 복구는 제공하지 않는다. 편집 충돌에서 입력은 현재 폼에 유지되지만 편집 중인 모든 폼의 종료 후 복구를 보장하지 않는다.
